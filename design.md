# Design System: Constellation Gate AI

> An operator's console for AI traffic: dense, neutral, data first.

How to use this file: the YAML above holds the tokens and is normative; the
literal values live in `src/index.css`. The sections below say where and why
to use them, in Google's DESIGN.md order (`npx @google/design.md lint
design.md` validates it). Implementation detail lives in each component's
header comment, routes and pages in `data-model.md`, owner-corrected UX
patterns in `plugins/ux-designer/skills/patterns/`. When this file and the
code disagree, the code shipped last: fix whichever is wrong, here first.

## Overview

The person on this screen runs an AI gateway in production. They inspect: they
filter, sort, drill in and copy. Every surface is built for scanning and
comparing, not persuading (impeccable's Operate mode). Content sits on white
cards over a near-white canvas, edged by a hairline and the faintest shadow.
Ink is neutral; color appears only to report a state, mark a plan tier or plot
a series. Numbers are mono and right-aligned; hero numbers are sans. Light and
dark themes ship together.

**Key characteristics:**

- Neutral-900 primary action, never blue.
- Dense: 16px is the dominant spacing, 36px the tallest control.
- Five type voices (heading, label, copy, mono, eyebrow); weight tops out at 500.
- Three radius tiers (6px controls, 8px cards, 16px modals) on a 4px grid.
- Tailwind's shadow scale, nothing bespoke.
- Light and dark from one set of semantic tokens.

## Similar Brands

Our look is Vercel, Linear and Factory combined, in OpenRouter's product category.

- **Vercel (vercel.com)**: the closest twin. Geist, monochrome ink, hairline borders, a 4px grid and compact density; we share the neutral primary and the mono labels.
- **Linear (linear.app)**: dense, precise product UI with quiet chrome and one accent. We follow its row-first lists and keyboard-ready controls; Linear runs dark by default, we run light first.
- **OpenRouter (openrouter.ai)**: the same product category, one gateway over many models. Its model catalog, provider rows and per-token pricing are the reference for ours.
- **Factory (factory.ai)**: the early inspiration. We share Geist, mono uppercase as the instrument voice (when you see mono, you are reading the system), color as data and never chrome, and flat 1px surfaces. Factory is a black canvas with 400-weight display type and 3px / 10px radii; we are light first, labels at 500, radii 6 / 8 / 16.

## Colors

Neutral ink on near-white, with color held back for meaning. Two layers live
in `src/index.css`: palette atoms in `@theme` (five OKLCH ramps of 11 steps,
plus the chart palette) and semantic tokens in `:root` and `.dark`. UI code
uses semantic tokens only; literals live only in `src/index.css`
(`.claude/rules/no-hardcoding.md`). Dark mode is a `.dark` class on `<html>`
that re-points the semantic tokens, so anything on a token flips for free.
The theme follows the OS until the user picks one with the top-bar toggle.

### Status info family

`bg-info` (StatusDot), `bg-info-wash` with `text-info-foreground` (Badge `info`), and `bg-info-surface`, `border-info-border`, `text-info-foreground-strong` (Callout fill, edge, ink and icon). These six are the only way to paint an info status; info is not a plan tier.

**The Wash Ladder Rule.** A status surface takes its wash by weight, and only
these three rungs exist in dark: 10% for a full-width alert banner, 15% for an
inline note, 20% for a badge. The border is always the 30% rung; the ink never
changes. A badge sitting on a banner may drop to the banner's 10%. The
destructive family writes `destructive/N` (it tracks the semantic token); the
warning family writes `warning-500/N`. Light twins: `bg-danger-50
border-danger-200` and `bg-warning-50 border-warning-200` for banners and
notes, the `-100` step for badges. A hover on a tinted fill is the `-200` step
light and `-500/25` dark; an ultralight large fill (`bg-*-25`) is `-500/10`
dark.

### Vendor brand colors

External brand hexes live in one registry, `src/components/icons/brand-colors.ts`, and paint `VendorAvatar` only. A chart may pin a series to a brand-mnemonic slot on purpose (Anthropic orange, OpenAI blue); otherwise series go by index.

**The Neutral Primary Rule.** The primary action is neutral-900 ink, never
blue. Blue means info, done, the active tab and the brand mark; links are ink
with a faint underline.

**The Semantic Token Rule.** Paint surfaces, borders, rings and text with
semantic tokens, never a raw ramp step: a raw step does not flip in dark. A
missing token is added to `src/index.css` (both themes) and this file first.

Don't:

- Write a hex, `rgb()`, `hsl()` or `oklch()` outside `src/index.css` (`lint:design` fails it).
- Use `bg-white`, `bg-neutral-100`, `border-neutral-200`, `ring-neutral-N`, `text-neutral-900`, `text-neutral-500` or `bg-neutral-900/N` in UI code (`lint:design` names the token).
- Write `bg-accent/50`, `border-destructive/70` or any `/[N%]` alpha. Use the named rung.
- Use `bg-background` inside a component, or put a `ToolCallCard` on it.
- Use chart colors for anything but chart series, or vendor colors as series by default.

**Kept as-is:** white text on brand or status fills, the fixed-dark terminal and auth surfaces on their own token families, and captured transcript strings in `src/data`. These are correct; do not sweep them.

## Typography

**Sans:** Geist (`--font-sans`) for everything people read and click.
**Mono:** Geist Mono (`--font-mono`) for data, ids, codes, badges and eyebrows.

**Character:** a quiet operator voice. Size and voice carry the hierarchy;
weight never goes past 500 and color is kept for state. Every text style is a
named voice in `src/index.css`. Pages use the voice, never a raw `text-*`,
`font-*` or `text-[Npx]` (`lint:design` fails it).

### Heading ladder

- **type-heading-32** (500, 32/40, tight): the page title (`PageTitle`, the one `h1`).
- **type-heading-24** (500, 24/32, snug): a section of a long page, a tab header.
- **type-heading-20** (500, 20/28, snug): a block title (`SectionTitle`, dialog titles, empty-state titles).
- **type-heading-16** (500, 16/24, snug): a card title (`CardTitle`).
- **type-heading-14** (500, 14/20): a small heading.
- **Display** (`type-heading-40` to `-72`, tight): marketing and auth surfaces only.
- **Retired:** `type-heading-18` and `type-heading-28`. Defined for the lint only; never use them.

### Voices

- **Label** (`type-label-12`, `-14`, `-16`, `-18`; 500): anything you can click, and anything that names something.
- **Copy** (`type-copy-12`, `-14`, `-16`, `-18`; 400): prose the user reads. `type-copy-14` is the default body.
- **Mono** (`type-mono-12`, `-14`, `-16`; 400, tabular): every data value: numbers, counts, currency, percentages, dates, ids, hashes, slugs.
- **Eyebrow** (mono 12px, 500, uppercase, 0.1em tracking, muted): KPI labels and nav-rail section headers. Never a form label.
- **Badge** (mono 12px, 500, uppercase, tabular): set by the `Badge` primitive.
- **Hero numeric** (sans 500, tabular, tight; 24px and 32px): set by `HeroNumeric`.
- **Input helper** (`type-input-helper`, 12/16, 8px under its field): the line under an input.
- **Micro tier** (`type-copy-10`, 10/14): two places only, the nav-rail upgrade card's sub-line and `Badge size="xs"`. A third needs a line here.

**The 12/18 Rule.** All three 12px voices (`type-copy-12`, `type-label-12`,
`type-mono-12`) share one 18px line box, so a caption, a label and a value in
one row sit on one baseline. Do not add a fourth 12px leading.

### Label voice: the enumeration

Apply this test in order: if you can click it or it names something, it is
**Label**; if it is prose, it is **Copy**; if it heads a section, it is
**Heading**. This list is the single source; the rules files cite it.

- **Label:** button labels; nav items, active and inactive; tabs; menu and select items; select, combobox, dialog, popover and menu triggers; standalone link-buttons ("Show more"); a clickable card or KPI tile; pagination controls; table column heads; card titles; form labels; `<dt>` terms; model, vendor, workspace, key and team-member display names.
- **Copy:** links inside a sentence; typed input values; a secondary identity line (the email under a name); `<dd>` values; table cell content; a table row's identifier cell, even when it opens the row (declared with a `design-allow-copy-voice` comment).
- **Eyebrow:** segmented control labels.

**The Quiet Label Rule.** A label that should recede goes `text-muted-foreground`
and stays 500. Color does the quiet work; weight does the structural work.

**The Machine String Rule.** Mono is for the string you would paste into a
config file (`anthropic/claude-opus-4.7`, `key_live_a1b2`, a hash). The human
name beside it ("Claude Opus 4.7", "OpenAI", a workspace name) is sans.

**The Size Gate Rule.** Hero numbers at 24px and above are sans tabular. Below
20px every number is mono, whatever its role.

### Exception: Ask AI reply prose

- Inline `code` and fenced blocks inside an agent reply (`ask-ai-message.tsx`) render in `type-copy-14` on a `bg-muted` chip. Long-form reading; scoped to that panel only.

### Exception: ToolResultCode

- Tool-result bodies in the Conversations trace are `type-copy-14` for the same reason. Every other transcript surface stays mono.

Don't:

- Reintroduce 18px or 28px headings, or any bracketed pixel size.
- Pass an arbitrary `-tracking-[Npx]` or sprinkle `tracking-tight`. Tracking comes from the voice: snug for 16 to 24px headings, tight for 32px and up, normal for 14px text and all mono.
- Use a 600 or 700 weight. Size carries hierarchy.
- Put a `type-copy-*` voice on a label (`lint:design` fails it), or set a voice on an ancestor `<dl>` so its `<dt>` inherits 400.
- Use raw `font-medium` or `text-sm` in `src/pages` or `src/layouts` without a voice; inline emphasis inside a voiced paragraph takes a `design-allow-raw-type` comment.
- Use 10px as a fallback for tight space. Write less copy or make room.

## Layout

A 4px grid, dense by default. Desktop-first (tuned for 1280px and up), fully
usable on a phone.

### Spacing

| Step | Value | Role |
| --- | --- | --- |
| `1` | 4px | Inside a primitive: icon to label, tight groups. |
| `2` | 8px | Dense siblings, badge and icon gaps. |
| `3` | 12px | Inside a primitive's row: button and input padding, inner table cells. |
| `4` | 16px | The default: card padding, page gutter on phones, section gap, gap between cards. |
| `6` | 24px | Outer page margin from `sm`, modal padding, between body sections. |
| `8` and up | 32px+ | Page bottom and rare large rhythm; justify each use. |

**The 16px Default Rule.** Start every surface gap and padding at 16px. Prefer
8px steps for layout rhythm; use the odd 4px steps (12, 20) inside a
primitive's own row or where 8px is too coarse.

**The Primitive Padding Rule.** Padding inside a primitive belongs to the
primitive (Card 16px, Dialog 24px or 16px compact, table cells 12px inner and
16px outer). Pages never override it.

### Page frame

- **Grid** (`grid grid-cols-12 gap-4`): composed pages; spans sum to 12.
- **Margins** (`px-4 sm:px-6`, `pt-6 pb-8`, `lg:pb-20`): set once on the shell `<main>` in `DashboardChrome.tsx`.
- **Page header**: `PageTitle`, then one subtitle sentence in `type-copy-16` muted, at most half the column wide.
- **Sidebar** (240px expanded, 64px collapsed, from `lg`): below `lg` it becomes a hamburger sheet and the logo moves to the top bar.

### Responsive

**The Column Not Viewport Rule.** `<main>` is a container. Page content
responds to its column with `@`-prefixed container variants, because the Ask
AI panel narrows the column while the window stays wide. A raw `sm:`, `md:`,
`lg:` or `xl:` on page layout is a defect. The viewport stays right for the
chrome (`DashboardChrome`, `AuthLayout`, `sidebar.tsx`), overlays, the Ask AI
panel internals and the outer margins.

| Use | Threshold | Behavior |
| --- | --- | --- |
| Table toolbars | `@2xl` (672px) | Below: title on its own line, full-width search. Above: one row. |
| Chart with legend | `@4xl` (896px) | Below: legend under the chart. Above: 8/12 chart, 4/12 legend. |
| Trend card header | `@2xl` (672px) | Below: controls drop to their own row. |

- **Named containers**: a nested surface that needs its own axis names it (`@container/connect`) and addresses it by name. `CardHeader` is already a named container.
- **Breakpoints** (chrome only): `xs` 450, `sm` 640 (margins step to 24px), `lg` 1024 (rail or hamburger), `xl` 1280 (the design target), `3xl` 1920.
- **Tables**: scroll sideways inside their card; a `table-fixed` table takes a `min-w-[Npx]` floor (1000px for 6 to 8 columns) so it scrolls instead of crushing.
- **Charts**: bar counts fold on a monotonic ladder by column width; axis ticks use recharts' own collision handling, derive from real data, and anchor the first and last labels inside the plot.
- **KPI numbers**: counts of a million and up render compact (`formatCompactCount`).

### Touch targets

- **Pointer**: controls are 24px minimum (WCAG 2.5.8 AA); dense chrome is 32px and default controls 36px. This is a desktop operator tool, so 44px is not the pointer target.
- **Coarse pointer**: full-width phone actions use `Button size="touch"` (44px); chat surfaces keep a 44px floor; every text field renders at 16px.
- **Small controls** (checkbox, radio, icon actions): a 16px or 24px visual with an invisible hit area that reaches at least 24px.

## Elevation & Depth

Depth comes from a hairline edge plus Tailwind's stock shadow scale, nothing
bespoke. The border carries the crisp edge in both themes; the shadow only
lifts.

| Tier | Recipe | Surfaces |
| --- | --- | --- |
| Flat | none | Sub-elements (tab triggers, badges, menu items), nested panels, `CodeCard`, `ToolCallCard`. |
| Card | `border border-border shadow-xs` | Card, KpiRail, EmptyState, CompactKpi, Tabs `line`, outline and default buttons. Tables sit inside a card and carry no shadow of their own. |
| Soft lift | `shadow-sm` | Button `raised` and `promo`, Card `elevation="raised"`, the scroll-to-latest key. |
| Menu | `shadow-md` | Menus, popovers, tooltips, Select content, chart tooltips. |
| Modal | `shadow-lg` | Dialog, AlertDialog, Sheet, the auth cards. |

**The Stock Shadow Rule.** The only shadows are `shadow-2xs`, `shadow-xs`,
`shadow-sm`, `shadow-md` and `shadow-lg` at Tailwind's own values, the same in
both themes. No arbitrary `shadow-[...]`, no inline `rgba()`. A surface that
looks edgeless is missing its border; do not reach for a bigger shadow. The
one allowed tweak is recoloring a stock step's ink on a component
(`shadow-(color:--promo-shadow)`).

### Focus ring

- **Recipe** (`focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background`): every focusable control. The ring is neutral (neutral-600 light, neutral-400 dark, about 7.5:1), never blue.
- **Inset** (`focus-visible:ring-inset`, plus `focus-visible:-outline-offset-1` where an outline also paints): a control that fills its parent edge to edge (table rows, tab triggers, a flush card child).

**The Clipping Rule.** Nothing may be cut off by an ancestor: not a focus ring,
not a tooltip or other floating layer, not a shadow, not a pressed or moved
state. Setting `overflow` on one axis clips the other too, and a ring is a
shadow 4px outside the box, so a clipped ring is simply gone. Two remedies
only: reserve the room (`p-1` with `-m-1`, or `scroll-py-1` on a scrollport),
or portal the layer to the body (every tooltip, popover, menu, select and
chart tooltip does). Removing the scroll or the overflow is not a remedy.
Enforced by `lint:design` checks 8 and 9, `npm run lint:clipping` and the
`design-invariants` suite; a real exception carries a `design-allow-clip`
comment with the measured reason.

## Motion

Animate intent, not decoration. The `animator` agent owns every animation and
builds to these values.

| Token | Value | Use |
| --- | --- | --- |
| `--ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | The default for color, shadow and scale; Tailwind `ease-out` maps to it. |
| `--ease-in-out` | `cubic-bezier(0.77, 0, 0.175, 1)` | Symmetric moves. |
| `--ease-drawer` | `cubic-bezier(0.32, 0.72, 0, 1)` | Slide-in surfaces (Sheet, sidebar, mobile notifications). |
| 100ms | | Overlay fade, menu item highlight. |
| 150ms | | Default control transition. |
| 200ms | | Dialog enter (fade and `zoom-in-95`), sliding tab indicator, toast. |
| 120ms | | Dialog close. |
| 300ms | | Sheet slide-in. |
| `active:scale-[0.98]` | | The press on Button, Card `interactive`, IconActionButton and tabs; never on a popup trigger. |
| 100ms stagger | | Route entrances where order means something (Models Featured cards); 50ms on the Gate Chat landing. Never on rows or frequent state. |

**The Real Properties Rule.** Transition only color, background, border,
opacity, `box-shadow`, `scale` and `transform`; never `transition-all`. Spell
real CSS properties in a list (`color`, not `colors`; `scale`, because Tailwind
v4 emits the press as the `scale` property).

**The Reduced Motion Rule.** Every transition and animation carries its
`motion-reduce:` off switch, and every press pairs with
`motion-reduce:active:scale-100`. Base UI exits also need
`data-closed:fill-mode-forwards` on popup and overlay.

## Shapes

| Token | Value | Use |
| --- | --- | --- |
| `rounded-xs` | 4px | Sub-elements: tab triggers, select and menu items, badges, a card nested in a card. |
| `rounded-sm` | 6px | Controls and chrome: buttons, inputs, select triggers, menus, popovers, tooltips. |
| `rounded-md` | 8px | Cards and surfaces: Card, KpiRail, table containers. |
| `rounded-lg` | 10px | The `--radius` base other tokens derive from. |
| `rounded-xl` | 16px | Modals: Dialog, AlertDialog. Locked. |
| `rounded-full` | full | Pills, dots, switch thumbs, monograms, round keys (`shape="circle"`). |

**The Step Down Rule.** A nested surface takes the next radius down: 16px modal,
8px well, 4px card inside it (full ladder 24, 16, 8, 4). Matching radii across a
parent and child is the bug. Override a shared primitive's radius at the usage
site, never in the primitive. Sheets sit flush (`rounded-none`).

**Icons.** `lucide-react` at stroke 1.75, one stroke for the whole set, passed
at every call site (`strokeWidth={1.75}`; lucide's default is 2). Sizes 12, 14,
16 and 20px (`size-3` to `size-5`). In a Button, mark the icon with
`data-icon="inline-start"` or `"inline-end"`.

## Components

Every primitive lives in `src/components/ui/` and is the closed set: compose
it, never rebuild it (`.claude/rules/no-handrolling.md`). Each file's header
comment holds the implementation detail and the history; this section holds
what to use, when, and the rules. A call-site `className` places a primitive
(`flex-1`, `w-full`, `ml-auto`, grid placement); it never restyles it.

**The Primitive Owns Its Look Rule.** Color, border, radius, shadow, padding,
gap and type come from the primitive's own props (`variant`, `size`, `tone`,
`density`, `shape`, `elevation`). If a design needs something they cannot
express, add a variant and record it here first.

### Buttons

`button.tsx`. Every `<Button>` passes an explicit `size`.

- **default** (`bg-primary`, `shadow-xs`, `rounded-sm` 6px, `px-3`): the one primary action per view.
- **outline** (`border-border bg-card shadow-xs`): secondary actions.
- **ghost**: tertiary actions in toolbars and menus.
- **secondary**: a filled, quieter alternative to `outline`.
- **link**: a standalone link-button. Links inside body text use `TextLink`.
- **destructive**: irreversible actions; quiet at rest, confirmed on use.
- **raised** (`bg-control-raised shadow-sm`): a control on a panel that must lift off it (composer add-context key, scroll-to-latest). Reach for `outline` first.
- **promo** (`--promo-cta-*` fill and border, `shadow-sm`): upgrade and plan actions only. Keep its border: it carries the edge in dark mode.
- **info-outline** (`border-info-border text-info-foreground-strong`, transparent): a control on an info `Callout`, never on a plain surface.
- **ghost-to-outline** (ghost below `lg`, outline from `lg`): the top bar's notifications bell only.
- **Sizes** (`xs` 24px, `sm` 32px, `default` 36px): `default` is the largest. Icon squares match (`icon-xs` 24, `icon-sm` 32, `icon` 36) with a 14px, 16px and inherited glyph.
- **touch** (44px, `h-11`): full-width actions in a phone-only layout.
- **icon-action** (32px below `lg`, 24px from `lg`): dense action rows only (message tools, Ask AI reply tools). Give the row `gap-0 px-0 lg:gap-1 lg:px-1` so the icons never move.
- **shape** (`default` 6px, `pill` and `circle` full): radius comes from `shape`, never a `rounded-full` class.
- **Icon padding** (10px both sides, `px-2.5` via `data-icon`): the one sanctioned half-step off the 4px grid.

**The 36px Ceiling Rule.** No Button, Input or Select is taller than 36px,
except `touch` on phone layouts and the 40px `lg` Select that leads a setup
step. A control that needs to be bigger is a row, a card or a tile. Ask before
adding a size.

**The Surface Shadow Rule.** Every variant with a fill or an edge carries
`shadow-xs`. Tinted variants (`destructive`, `promo`, `info-outline`) carry
none of their own, and `raised` keeps `shadow-sm`.

**The One Responsive Entry Rule.** `icon-action` is the only responsive size
and `ghost-to-outline` the only responsive variant. A second one needs a
written reason here.

### Inputs and forms

- **Input** (`input.tsx`; 36px `h-9`, `px-3`, `bg-muted`): one size, no `size` prop. `variant="elevated"` (`bg-card shadow-xs`) for a search field outside a card on the page background.
- **Textarea** (`textarea.tsx`): the Input surface, growing with its content.
- **InputGroup** (`input-group.tsx`; 36px): an Input with an icon, key hint or button attached.
- **Field** (`field.tsx`): label, description, error and control as one unit, 16px between fields. Group related fields in `FieldSet` with a `FieldLegend`.
- **Label** (`label.tsx`; `font-medium`): pairs one-to-one with a single control.
- **Field group label** (`FieldLegend variant="label"`, muted): names a group of controls that sits under it (preset tiles, a slider, a segmented control). It stays quiet so the values lead.
- **Checkbox** (`checkbox.tsx`; 16px): checked and indeterminate share the `bg-primary` fill; only the glyph differs. Use `indeterminate` for a some-but-not-all select-all.
- **Radio** (`radio-group.tsx`; 16px): `indicator="check"` (24px, a filled check) marks a whole selectable card from its corner. A card-sized option is a `<label>` around a `RadioGroupItem`.
- **Switch** (`switch.tsx`; `sm`, `default`, `lg`): sized to its thumb, unrelated to the 36px control ladder.
- **Validation** (`aria-invalid`: `border-destructive` plus the destructive ring): the field shows the state, and `FieldError` says what is wrong and how to fix it. Titles and labels never turn red.
- **Touch text size**: every text field renders at 16px on a coarse pointer, so iOS never zooms the page.

**The Disabled State Rule.** Base UI controls are not native elements, so
`disabled:` never matches them. Style disabled Base UI controls with
`data-disabled:`.

### Selectors

- **Select** (`select.tsx`; `sm` 32px, `default` 36px, `lg` 40px): the default single choice. `sm` is for dense chrome (rows-per-page, date-range month pickers); `lg` only for a lone field that leads a setup step. The chevron turns while open; the field label never uses `htmlFor` on the trigger (that would open it), the trigger takes an `aria-label`.
- **MultiSelect** (`multi-select.tsx`): a checkbox list on a popover, flush beside a Select. Options may carry a `description` line. Opt-in props: `maxVisibleOptions`, `selectAll`, `commitMode` (Apply / Cancel footer), `minSelected`, `showSelectedLabels`, `popupWidth`.
- **Combobox** (`combobox.tsx`): a searchable single choice for long lists (the Claude Code model picker). Same popup and rows as Select.
- **Tabs, line** (`tabs.tsx`, `variant="line"`): sibling sub-pages of one surface, each of which could have its own URL. The active trigger never takes a hover fill.
- **Tabs, default** (pill on a well): rare; a nested tab strip inside a card where line tabs would compete with the chrome.
- **TabsCount** (`tabs-count.tsx`; mono): the count chip inside a tab trigger.
- **Segmented** (`segmented.tsx`) and **SegmentedPill** (`segmented-pill.tsx`; bordered track): mutually exclusive views of the same data (time range, chart type, unit), inside a toolbar or panel, never as an extra row.
- **MiniRadioGroup** (`mini-radio-group.tsx`; 32px card track, muted thumb): a true single-choice radio group in a compact bar. One consumer (the BYOK / pay-as-you-go switch); reconcile with Segmented before adding a second.
- **OptionTile** (`option-tile.tsx`; `md` 40px, `lg` 48px): one choice in a `radiogroup` of tiles. `tone="neutral"` or `"accent"` (the two tones are an open decision).
- **ToggleGroup** (`toggle-group.tsx`): 2 to 5 toggled options.

**The Page or Lens Rule.** If each option deserves its own URL, it is a line
tab. If the options are alternate views of the same data, it is segmented.

**The Overlay Placement Rule.** Select, Popover, Menu and the date picker open
below the trigger, right-aligned, 8px away, and flip up near the viewport
edge. Left-anchored triggers (workspace switcher, side user menu) keep their
start alignment.

**The Toolbar Rule.** Search on the left at a fixed width (`SearchInput`,
384px), filters next to it, sort anchored far right (`ml-auto`). Filter
selects in a dense toolbar show the chevron only, no leading icon. Hide the
toolbar when the table is empty.

### Cards and containers

- **Card** (`card.tsx`; `rounded-md` 8px, `border-border`, `bg-card`, `shadow-xs`, 16px padding): the surface for every grouped block. Cards never touch: 16px (`gap-4`) between cards.
- **density** (`default` 16px rhythm, `flush` none): `flush` when a Table or a full-bleed feed fills the card and brings its own hairlines.
- **size** (`sm`, 12px rhythm): compact cards.
- **tone** (`default`, `danger`, `pro`, `enterprise`): edge only. `danger` (`border-destructive-subtle`) frames irreversible actions; `pro` and `enterprise` mark the "Your plan" card on the matching Billing page.
- **interactive**: the whole card is one click target; it takes the table-row hover and the 0.98 press. Focus stays on the interactive child.
- **elevation** (`default` `shadow-xs`, `raised` `shadow-sm`): `raised` for a standalone choice card on a phone layout.
- **CardHeader** (4px between title and description, 8px to the `CardAction`): `CardAction` holds actions only, never a total or a count.
- **CardFooter** (16px, no border, no wash): spacing separates it. A footer holds only actions on that card's own object.
- **KpiRail** (`kpi-rail.tsx`; 2 to 6 columns): one bordered row of tiles split by inset hairlines that stop short of the corners.
- **CodeCard** (`code-card.tsx`): a code preview with a header strip and a copy button, flat.
- **SidebarUpgradeCard** (`sidebar-upgrade-card.tsx`; `--promo-*` border and texture): the one branded surface in the nav rail, shown only on Free and Default. Its words stay neutral; the blue lives in the chrome.

**The Locked Padding Rule.** Never pass padding or gap classes to `Card`,
`CardHeader`, `CardContent` or `CardFooter` from a page. A surface that needs
another rhythm gets a variant.

**The Facts Are Rows Rule.** Inside a card, every count, price, period or date
is a label-value row (`DetailList`), not a sentence and not a tile.

### Lists and tables

- **Table** (`table.tsx`): always inside `Card density="flush"`. Header row 40px (`type-label-12`, muted, sentence case); body rows at least 48px; outer cells 16px, inner 12px. Scroll shadows appear only when the table overflows.
- **Row hover** (`hover:bg-accent-muted`): owned by `TableRow`; a page passes `cursor-pointer` at most.
- **SortableTableHead** (`table.tsx`): every sortable column. Click cycles ascending, descending, unsorted; the click target is the label width only. Numeric columns put the arrow left of the label so the label stays flush right. Pairs with `useTableSort`.
- **RowActionButton** (`row-action-button.tsx`; `layout` `row`, `stack`, `inline`): a row that opens something puts a real button in its identifier cell; the `<tr>` never takes `role="button"`.
- **TablePaginationFooter** (`table-pagination-footer.tsx`): the only pagination chrome. The page strip renders only when there is more than one page; the count line always stays.
- **TableEmptyState** (`table-empty-state.tsx`): the empty state for every table card, for a fresh workspace and for a filter with no matches alike. Title `No {things}`; the body says what will appear. Hide the toolbar and the pagination footer with it.
- **Bulk select**: a leading checkbox column, a select-all for the visible page only, cleared on page, page-size and tab change. The selection banner is the first body row and pushes the rows down. Spell both numbers ("Move 1 notification", "Move 3 notifications").
- **DetailList** (`detail-list.tsx`; `boxed` in a modal, `flush` in a card): label and value on one row; on a wide flush list the value sits flush right in tabular figures, and on a narrow list it stacks under its label.
- **Cell ink**: the row identifier and body data in `text-foreground`; context fragments (a sub-id, a separator) in `text-muted-foreground`; a missing value is a muted dash with an `sr-only` meaning.
- **Numbers**: numeric columns are mono tabular and right-aligned, head and cells alike. A conditional indicator (a slow-row icon) gets a fixed leading slot on every row so digits never shift.
- **SearchInput** (`search-input.tsx`; 36px, 384px wide): the toolbar search.
- **Timestamp** (`timestamp.tsx`): every date or time in a table. Absolute by default, relative in the tooltip; `format="dateNumeric"` for dense rows; `null` reads "Never".
- **Monogram** (`monogram.tsx`; `sm` 16px, `md` 28px): an initials chip, always next to the name it stands for.

**The Header Is Not a Hit Target Rule.** Header rows are 40px label strips;
body rows are 48px targets. Do not equalize them.

### Overlays and menus

- **Popover** (`popover.tsx`; `rounded-sm bg-popover shadow-md`): anchored panels (date range, notifications). `positionerClassName` moves where a panel sits at a breakpoint and nothing else.
- **Tooltip** (`tooltip.tsx`; `rounded-sm bg-popover shadow-md`): required on every Timestamp, every truncated identifier and every dash that hides a reason. A trigger that holds keyboard-relevant content takes `tabIndex={0}`.
- **Menu** (`menu.tsx`; items 32px, `bg-accent-muted` highlight): action lists. `active` marks the current row (the chat you are in, the workspace you are on); `variant="destructive"` for Sign out.
- **UserMenu** (`user-menu.tsx`): one menu, opened from the sidebar user row and the top-bar avatar.
- **Separator** (`separator.tsx`; 1px `bg-border`): rare; most rhythm comes from spacing and `border-t`.

**The Closing Flicker Rule.** Every Base UI popup and overlay carries
`data-closed:fill-mode-forwards`, or it flashes on close.

### Dialogs and sheets

- **Dialog** (`dialog.tsx`; `rounded-xl` 16px, `shadow-lg`, overlay `bg-neutral-900/40 backdrop-blur-xs`): confirmation and short tasks. `density="default"` 24px is the modal shape; `density="compact"` 16px is a single-control dialog.
- **DialogScrollContent** (max 90vh): detail modals. Fixed header, scrolling body, fixed footer.
- **DialogTitleBlock**: every modal title (`icon`, `badge`, `meta` slots; `titleFont="mono"` when the title is an id). No eyebrow above a modal title.
- **DialogFooter** (24px above, no border): short modals.
- **DialogScrollFooter** (`py-4`, `border-t`): the action band under scrolling content.
- **Close button** (`absolute top-3 right-3`, ghost `icon-sm`): rendered by the primitive; never hand-built. A non-X dismiss sets `showCloseButton={false}` and composes `DialogClose`.
- **Body sections** (`SectionHeading`, 12px to content, 24px between sections).
- **AlertDialog** (`alert-dialog.tsx`; modal tier): destructive confirmations.
- **Sheet** (`sheet.tsx`; flush to the right edge): inspection that persists while reading.

**The Inspect or Confirm Rule.** A sheet is for inspecting a row while the
page stays in view. A dialog is for confirming, or for a paired cross-link
inspection. Never open a modal as the first idea.

### Badges and status

- **Badge** (`badge.tsx`; 20px, `rounded-xs`, `px-2`, mono uppercase): status, counters and codes. A capability or category label (Vision, Streaming) may carry a 12px icon; a status badge is text only.
- **Badge tones**: `default`, `secondary`, `outline`, `ghost`, `link`, `success`, `warning`, `destructive`, `info`, `neutral`. Plan tiers use `pro` and `enterprise` (named by role: a tier is not a status); Free and Default use `neutral`.
- **Badge size** (`xs`, 16px): the Featured-card tagline only.
- **StatusBadge** (`status-badge.tsx`): ON / OFF with a check or slash glyph, the one badge that carries an icon.
- **StatusDot** (`status-dot.tsx`; 6px or 8px): a standalone state dot in a row or a live rail. Never inside a Badge.
- **DeltaTag** (`compact-kpi.tsx`): a KPI change with arrow, sign and color together. `inverted` only for rate metrics where rising is unambiguously bad (latency, error rate, cost per request); volume metrics stay sign-based. No "lower is better" text.

**The Tone Is the Signal Rule.** Never nest a StatusDot or a status glyph inside
a Badge (`StatusBadge` is the one ON / OFF exception). The tone carries the
status; the primitive sets the case.

### Feedback and loading

- **Callout** (`callout.tsx`; `--info-*` wash, border and ink, 16px Info glyph): a persistent fact about the surface it sits on (an organization lock, a retention statement). `role="note"`, no dismiss. Optional `action`: one `info-outline` button at its right edge.
- **Status banners** (`BudgetBreachBanner` and peers): warnings and errors keep their own status component; Callout has no tone prop.
- **Toast** (`sonner.tsx`; bottom right, follows the theme): a short report of an event. Errors stay until dismissed.
- **EmptyState** (`empty-state.tsx`): a page-level empty state. Inside a table card use `TableEmptyState`.

### Skeleton

- **Skeleton** (`skeleton.tsx`; `animate-pulse`, `bg-muted`): the only loading motion. `SkeletonText` holds a value's line box so nothing shifts; KPI primitives take a `loading` prop.

**The Skeleton the Value Rule.** Titles, column heads, toolbars, tabs, units and
empty-state copy render as themselves while loading; only what the request
answers (numbers, names, times, fills, charts) becomes a skeleton of the same
box. Render one skeleton row per row that is coming, so nothing jumps when the
data lands. A chart or meter keeps its box and drops `role="meter"` while
loading. An empty state waits for loading to finish. Announce loading once per
page with one `sr-only` status; never a spinner, never visible "Loading" text.

### Numbers, KPIs and charts

- **HeroNumeric** (`hero-numeric.tsx`; `default` 24px, `lg` 32px, sans tabular): every hero number. Never below 20px.
- **KpiTile** (`kpi-tile.tsx`): the tile for a `KpiRail`. Eyebrow title (optional live dot), HeroNumeric value, optional unit suffix, DeltaTag, caption and spark.
- **CompactKpi** and **CompactSpark** (`compact-kpi.tsx`): a leaner KPI and a 36px recharts spark, when the KpiTile slots do not apply.
- **Chart colors**: series use the chart palette (`--chart-1` and on), never semantic status ramps.

**The One Source Rule.** A KPI, its chart and its bars read from one data source
and must reconcile.

### Data bars & meters

- **Track** (`h-1.5 w-full overflow-hidden rounded-full bg-muted`; list-column meters `h-2 w-24`).
- **Fill** (`h-full rounded-full bg-gradient-to-r`, darker at the origin, lighter at the leading edge): status families run the 500 step to the 400 step (`from-success-500 to-success-400`); chart colors run `from-chart-N to-chart-N-soft`.
- **Width** (an inline `style` width): the only inline style a bar carries; the fill is a class string, never an inline color.
- **Breached budget** (`bg-destructive`): the one solid fill.
- **Not bars**: slider rails, chart series, sparklines, the tab indicator and decorative dots.

### Chart tooltip & legend

- **Tooltip** (`ChartTooltip` and `ChartTooltipContent` in `chart.tsx`): the only tooltip a chart may use. Menu-tier box (`rounded-sm border-border bg-card px-3 py-2 shadow-md`), `type-label-12` date in foreground, round 8px swatch, `type-copy-12` series name in muted, `type-mono-12` values right-aligned. `hideIndicator` for single-series sparks.
- **Dates** (`formatChartTooltipDate` in `lib/formatters.ts`): one shape on every chart; the year only when the range crosses a year.
- **Legend swatch** (8px, `rounded-full`): the same color source as the tooltip swatch. Never square.

**The Portal Tooltip Rule.** Chart tooltips render in a `document.body` portal
and position themselves. Never pass `position`, `wrapperStyle` or
`allowEscapeViewBox`, never import `Tooltip` from `recharts` outside `chart.tsx`
(`lint:design` check 7). Never pass a `formatter` that returns JSX, mute the
date label, or use a 14px voice inside the box.

### Type primitives

- **PageTitle** (`page-title.tsx`; `type-heading-32`, the page's one `h1`).
- **SectionTitle** (`section-title.tsx`; `type-heading-20`, `h3`, or `h2` when the section has sub-headings).
- **CardTitle** (16px, `font-medium`): the title of a card.
- **SectionHeading** (`section-heading.tsx`; `type-label-14`, `h3`): a section inside a modal body.
- **Eyebrow** (`eyebrow.tsx`; mono 12px uppercase tracked, muted): KPI labels and nav-rail section headers only. Never a card title, never a form label.
- **InlineCode** (`inline-code.tsx`; mono chip): a short identifier inside prose.
- **ToolResultCode** (`tool-result-code.tsx`; `type-copy-14`, word breaks): tool-result text in the conversation trace.

### Links and small actions

- **TextLink** (`text-link.tsx`; foreground ink, faint permanent underline): links inside body text. A `<button>` by default; `as="a"` for real navigation. Never blue: blue means info, done, active tab and focus.
- **BackLink** (`back-link.tsx`; muted label with a chevron): the breadcrumb back from a detail page. No underline.
- **IconActionButton** (`icon-action-button.tsx`; 24px with a hit area past 40px): a quiet icon action in a row. `aria-label` is required.
- **CopyButton** (`copy-button.tsx`; `mode="icon"` sizes `icon-sm`, `icon-action`, `inline-xs`; `mode="label"` sizes `compact`, `sm`, `segment`): the only copy control. Success reads "Copied!".
- **SettingsRow** (`settings-row.tsx`): title and helper left, control right, hairline between rows.

### Conversation parts

- **MessageBlock** (`message-block.tsx`; bordered bubble, `bg-card-muted`): a turn in the Conversations trace. The tools row (copy, expand) sits under the bubble, always visible.
- **ToolCallCard** (`tool-call-card.tsx`; `rounded-xs`, `bg-card`, mono 14px, three-line clamp): a tool call inside an assistant bubble, args verbatim. It inverts against its muted parent, so never place it on `bg-background`.

### Brand marks

- **Logo mark** (`LogoMarkLink` in `top-bar-brand.tsx`; `text-blue-700`, 32px in the sidebar): never rotated, recolored outside the approved tones, or given a shadow.
- **VendorAvatar** (`icons/vendor-meta.tsx`; 16px bare brand icon): a model vendor next to its name. No chip, no tone prop.

### Page recipes

Recipes that belong to one page live in that page's file header, not here:
the budget meter, bands, warn tick and breach banner
(`src/pages/teams/budget.tsx`, `budget-band.ts`) and the Token savings
Summary card (`src/pages/token-savings/SummaryCard.tsx`).

## Do's and Don'ts

### Do

- **Do** bind every color, space, radius, shadow and type value to a token or voice; `src/index.css` holds the only literals.
- **Do** build from a primitive in `src/components/ui/`; when it cannot express the design, add a variant and record it here first.
- **Do** give each view one primary action; the rest are outline or ghost.
- **Do** put an action on the container whose object it changes; a card footer holds only actions on that card's own object.
- **Do** say each value once per surface; every element says something only it says.
- **Do** right-align numeric columns in mono tabular figures.
- **Do** use exactly one `h1` per page, the `PageTitle`; choose heading tags for the outline and voices for the look.
- **Do** render pagination and inline links as `<button>`; there is no router.
- **Do** pick chart colors by series index, not by entity.
- **Do** check every state of a surface on every plan tier (Free, Default, Pro, Enterprise) and both themes before calling it done.

### Don't

- **Don't** use blue for a primary action or a link.
- **Don't** restyle a primitive at the call site (color, border, radius, shadow, padding, weight, size).
- **Don't** hand-roll a recipe twice; extract the primitive before the second copy.
- **Don't** put `role="button"` on a `<tr>`; put a button in the identifier cell.
- **Don't** nest a card inside a card at the same radius, or frame a panel inside a framed card; flatten to hairline sections.
- **Don't** use a raw ramp step where a semantic token exists; it will not flip in dark.
- **Don't** show a synthetic number; every figure derives from a real data row, and a KPI, its chart and its bars reconcile.
- **Don't** offer a revoked key in any picker.

### Reject these reflexes

- **The tile grid**: one label and one value per tile, in a row of boxes. Facts are a label-value list.
- **The sentence title**: a full sentence where a short noun phrase belongs.
- **The echo**: one number or idea repeated in the subtitle, the body and the footer.
- **The dead input**: a disabled field shown for a setting the user cannot change. Show the value as text with one line on what unlocks it.
- **The foreign action**: an upgrade or page action placed in another card's footer.
- **The everything-foreground screen**: every label and value in full ink, so nothing leads.
- **The status costume**: a plan tier painted with a success, warning or info color.
- **The decorative chart**: a dial, donut or ring where a number or a bar says it plainly.
- **The invented pattern**: a layout no tested product uses, built instead of the one Vercel, Stripe, Linear or OpenRouter users already know.

## Voice & Content

Copy is part of the design: precise, plain, no superlatives. The `copywriter`
agent writes every user-facing string.

- **Case**: sentence case for titles, labels, buttons, tabs and column heads; proper nouns and acronyms keep theirs (`API keys`, `LLM`, `Gate`). Uppercase only in eyebrows, KPI labels and badges.
- **Periods**: a complete sentence ends with one (subtitles, helpers, body, tooltips); a fragment does not (titles, labels, buttons, tabs, captions, badges, column heads).
- **Actions**: a specific verb and object (`Export view`, `Copy proof JSON`), never a bare `OK` or `Confirm`.
- **Terms**: the user-facing word is "fingerprint"; the code keeps `anchor`. Never rename across that line.
- **Unknown values**: a missing or unmetered value is a dash with a tooltip saying why, never an estimate.
- **Errors**: what happened and how to fix it, quoting the real requirement; show real status codes (`200`, `500`).
- **Names**: no real people's names in UI, data or copy; use roles and placeholders.

## Agent Quick Reference

- **Canvas:** `bg-background`. **Card:** `bg-card` with `border-border` and `shadow-xs`, 8px radius, 16px padding.
- **Text:** `text-foreground`; supporting text `text-muted-foreground`.
- **Primary action:** `Button` default (neutral-900 ink); one per view.
- **Numbers:** mono tabular, right-aligned in tables; hero numbers sans via `HeroNumeric`.
- **Color:** only for state (success, warning, danger, info), plan tier (Pro blue, Enterprise violet) and chart series.
- **Before building a feature:** read the matching entry in `plugins/ux-designer/skills/patterns/` and cite it in the spec.
